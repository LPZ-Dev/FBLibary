# Fat Buds Team Orchestration SOP

เมื่อถูกเรียกใช้งานด้วยคำสั่ง `/fb-team` ให้ดำเนินการตามลำดับดังนี้:

## ขั้นที่ 1: ตรวจสอบสมุดส่งกะ (Filesystem as Source of Truth)
- อ่านไฟล์ `handoff.md` (ถ้ามี) เพื่อเช็กบริบทล่าสุดของโปรเจ็กต์ก่อนเริ่มวางแผน

## ขั้นที่ 2: กระจายงานขนาน (Parallel Sub-agents ด้วยโมเดล `flash`)
สั่ง `invoke_subagent` เรียกลูกทีม 3 ตัวพร้อมกันในรอบเดียว โดยล็อกแฟ้มข้อมูลตามกฎ `1 Sub-agent = 1 Source`:
1. **🦀 ปู (Crab):** อ่านเฉพาะโฟลเดอร์ `sources/` เพื่อวิเคราะห์โครงสร้างข้อมูล SOP ทั้ง 6 สาขา และเตรียมรูปแบบข้อมูลที่รองรับการแก้ไขจาก Admin (ต้องระบุ `source: sources/...`)
2. **🐢 เต่า (Turtle):** อ่านโค้ดหน้าเว็บปัจจุบันร่วมกับ `.agents/skills/ui-polish/SKILL.md` เพื่อออกแบบ UI/UX ที่รองรับมือถือ, ใช้ `tabular-nums`, ช่องกรอกขนาด `16px+` และปุ่มกดตอบสนองไวในโซนนิ้วโป้ง
3. **🪼 แมงกะพรุน (Jellyfish):** ตรวจสอบ `package.json` และโครงสร้างโปรเจกต์ เพื่อวางเกณฑ์ความปลอดภัยสิทธิ์ Admin, ตรวจ Static Integrity และกำหนดขั้นตอนทดสอบด้วย `npm run build` โดยไม่ใช้ Headless Browser

## ขั้นที่ 3: สังเคราะห์แผนโดย 🐙 หมึก (Octopus)
- รวมผลลัพธ์จาก ปู, เต่า และ แมงกะพรุน เข้าด้วยกัน
- สรุปเป็น **Implementation Plan** ที่ระบุ:
  - รายชื่อไฟล์ที่จะสร้างหรือแก้ไขทั้งหมด
  - **Kill Conditions** (สิ่งที่ห้ามทำเพื่อกันเว็บอืดหรือระบบบวม)
- **หยุดรอการกด Approve** จากเจ้าของโปรเจ็กต์ใน Planning Mode ก่อนลงมือเขียนโค้ดจริงทุกครั้ง
